## 括号马拉松第十四天：外壳删掉，风景留下

“有效括号字符串”“原语化分解”“`s = P_1 + P_2 + ... + P_k`”——这味儿太像编译原理了。

读到“原语”俩字，我甚至想翻出镇宅宝典《龙书》，顺手再给括号画一棵红黑树，平衡一下心情。

好在冲动之前，我瞄了一眼例子。

哦，就是把每个有效括号块最外面那对括号删了。

#### 一、一个 `depth` 剥掉外壳

别递归，别建树，别召唤龙。一个变量 `depth` 就够——记录当前嵌套了几层：遇到`(` 就 `+1`，`)` 就 `-1`。

原语就是不能再拆的有效括号块。每个原语，都是 `depth` 从 0 出发、第一次又回到 0 的一小段旅程。

出发那一步的 `(` 和回来那一步的 `)`，是这趟旅程的外壳，要删；旅途中 `depth > 0` 时经过的括号，是沿途风景，全部留下。

怎么分辨哪一步是“出发”、哪一步是“回来”？盯住 `depth` 归零的瞬间：

- 遇到 `(`，先看 `depth`：`depth == 0` 是原语开头，不记；`depth > 0` 是原语内部，记下来。然后再 `depth += 1`。
- 遇到 `)`，先 `depth -= 1`：减完 `depth == 0` 是原语结尾，不记；减完 `depth > 0` 是原语内部，记下来。

注意：`(` 是**先判断、再 +1**；`)` 是**先 -1、再判断**。判断时机要卡住 0 的边界，早一步晚一步都认不出来。

写反了会怎样？外壳当内瓤留着，内瓤当外壳删掉，输出一份行为艺术，判题机看了直呼抽象。

```python
class Solution:
    def removeOuterParentheses(self, s: str) -> str:
        res = []
        depth = 0

        for ch in s:
            if ch == '(':
                if depth > 0:        # 不是原语开头，才记
                    res.append(ch)
                depth += 1
            else:
                depth -= 1
                if depth > 0:        # 不是原语结尾，才记
                    res.append(ch)

        return ''.join(res)
```

时间 O(n)，一趟扫完；空间 O(n) 装结果，额外变量 O(1)。

#### 二、字符串 `+=` 的温柔一刀

第一版代码我本来是这么写的：

```python
res = ''
for ch in s:
    ...
    res += ch      # 看着人畜无害
return res
```

看着挺乖，实则是个隐藏刺客。

Python 字符串不可变。每次 `+=`，都不能原地改，只能：申请新内存 → 拷旧串 → 追加新字符 → 扔旧串。

翻译一下：为了加一把椅子，你重新盖了栋房子，把旧家具全搬过去，摆上新椅子，再回头炸掉旧房子。

第 `k` 次拼接要拷 `k` 个字符，`n` 次下来总拷贝量是：`1 + 2 + ... + n = O(n^2)`。算法本是 O(n) 的，硬是被一行拼接拖成 O(n^2)——拷到天荒地老，TLE 到海枯石烂。

虽然 CPython 有针对 `s += x` 的就地扩容优化，但它只在这串字符串引用计数为 1、且布局可扩容时才触发，属于“看心情生效”的实现细节，标准不保证。

换成列表 `append` + 最后 `join` 就稳了：

- `list.append()` 是均摊 O(1) 的原地操作。
- `''.join()` 最后一次性分配好内存，一趟拷完。
- 总量回到 O(n)。

所以，别赌解释器的优化：要拼字符串，先攒进列表，最后 `join` 一把梭。

#### 尾声

一个原语，说白了就是一段从 `depth = 0` 出发、绕一圈、再回到 0 的短途旅行。

刚过去的国庆长假，其实就是一道现成的原语。

出发那天和返程那天，是外壳：堵在高速上，卡在收费站，删了不心疼。

真正算数的，是中间那几天——看山、看海、看人山人海。

现在 `depth` 归零，假期这道原语扫描完毕，外壳自动删除，你被 `join` 回了工位，连工位上的灰都没来得及换个姿势。
