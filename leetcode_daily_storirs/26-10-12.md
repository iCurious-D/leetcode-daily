## 轨迹算不完，就算守恒量

「困难」俩字，我没慌——力扣的困难题，又不是没写过。

「AND 和 OR」，我也没慌——位运算而已，见多了。

「任意次操作」——等等。前两个只是烧脑，这一个直接自由度爆炸 ？！

深呼吸。费曼说过，“shut up and calculate” ——慌什么，干就完了。

> 选两个下标 `i` 和 `j`，把 `nums[i]` 更新为两数的 AND，同时把 `nums[j]` 更新为两数的 OR。可以重复任意次。最后挑 `k` 个数，让平方和最大。

这操作其实挺有意思：两个数一碰，一个只留交集，另一个收走并集。

跑一个例子找找手感：拿 2（`0010`）和 8（`1000`）碰一下，AND 得 `0`，OR 得 10（`1010`）。一个被掏空，一个吃成胖子——这画面像极了粒子对撞：两颗粒子轰在一起，交换完信息，各奔东西。

可惜，这不是大型强子对撞机，而是大型算力黑洞。数据范围 `10^5`，两两组合 `10^10` 种，操作次数还不设上限——对不起费曼老师，这次 calculate 是真 cal 不完。

好在，物理界还有个祖传外挂：轨迹算不完，就算守恒量。自由度爆炸没关系，守恒量是锚点。

问题是，这场比特对撞实验里，谁是守恒的？

------

#### 一、守恒：不追轨迹，只找锚点

想找守恒量，先得看懂这场对撞的“相互作用” ：什么变了，什么没变。

这里的相互作用，就是 AND 和 OR。

位运算有个好习惯：**按位独立干活**——第 `b` 位的结果只取决于两个数的第 `b` 位，跟其他位毫无瓜葛。每个比特位就像一个独立的小宇宙，只跟同一位的粒子互动。

既然各位互不干涉，盯住任意一个二进制位，两个数在这一位翻来覆去，无非四种剧本：

- `(0,0) -> (0,0)`：无事发生
- `(1,1) -> (1,1)`：无事发生
- `(0,1) -> (0,1)`：无事发生
- `(1,0) -> (0,1)`：一颗 `1` 从 `nums[i]` 跳槽到了 `nums[j]` 

第四种看似剧变，实则搬家——`1` 既没被消灭，也没被创生，只是换了个宿主，从 `nums[i]` 迁到 `nums[j]`。

四种剧本穷尽了所有可能。所以不管撞多少次、按什么顺序，对于整个数组来说，每一位上 `1` 的总数纹丝不动。

这就是这场大型比特对撞的守恒荷：「每一位上有多少个 1」。

找到了锚点，扫一遍数组就能盘清家底：

```python
m = max(nums).bit_length()
cnt = [0] * m
for num in nums:
    for i in range(m):
        cnt[i] += (num >> i) & 1 
```

库存固定，剩下的问题只有一个：怎么重新分配这些 `1`，构造出 `k` 个数，让它们的平方和最大？

------

#### 二、凝聚：平方面前，抱团取暖

关键在「平方」俩字。

平方是**凸**函数——它偏爱极端，讨厌平均：`(a+b)² > a² + b²`，资源集中到一个数里，比分散到两个数里更赚。比如，一个 `1` 和一个 `2`，分开 `1² + 2² = 5`；把它俩塞进一个数，拼成 `3`，平方是 `3² = 9`，从 5 变 9，直接涨 4。

也就是说，每一个 `1`，挪进更大的数里贡献更大。平方世界的马太效应：凡有的，还要加给他，叫他有余。

所以，既然每一位上的 `1` 库存守恒，又要平方和最大，那就得**让不同位的 `1` 尽量抱团，往同一个数里塞**。注意，二进制里，同一位只能有一个 `1`，所以不能全塞进一个数，只能跨位抱团。

怎么塞？每一轮，从所有 `cnt[b] > 0` 的位各取一颗 `1`，拼成当前数 `x`，再把对应库存减一。重复 `k` 轮。

这样，第一轮会把所有还有库存的位全部收进来，拼出一个位最全的数；第二轮再收一遍还能收的位；以此类推。

```python
MOD = 10 ** 9 + 7
ans = 0
for _ in range(k):
    x = 0
    for i in range(m):
        if cnt[i]:
            cnt[i] -= 1
            x |= 1 << i
    ans = (ans + x * x) % MOD
return ans
```

时间复杂度 `O(n·m + k·m)`，空间 `O(m)`，`m` 是最大数的二进制位数。
