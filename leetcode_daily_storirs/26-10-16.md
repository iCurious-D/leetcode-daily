## 从扁平化管理到树状汇报：n 扩大一千倍后的组织变革

> 给你一个整数数组 `nums`，要求所有子数组 `nums[j..i]` 的“不同元素个数”的平方和，最后对 `1e9+7` 取模。
> 翻译一下：把所有连续子数组都拉出来，数数里面有几个不同的数，平方一下，全加起来。

兄弟们，2916 这题表面是个数组题，实际是异世界公司管理模拟器。

`n ≤ 100` 的时候，双层 for 直接枚举，干就完了。就像一百人的创业公司，扁平化管理完全够用：老板每天挨个拍肩膀问进度，一百人嗷嗷干，还能扛。

但 `n = 1e5` 的时候，你还搁那儿双层 for 硬套？这就像公司涨到十万人，还让老板每天挨个问“你今天干了啥”——你猜是老板先问完，还是你先被优化？

所以得换个思路。十万人的公司要活下去，只有一条路：**加中层。**

老板不再认识你。老板认识 2 个副总，副总认识 4 个总监，总监认识 8 个经理……一层层往下包，直到最底层的组长，手里正好管着你这一亩三分地。

而这种能二分区间、逐层汇总的组织架构树，在算法界有个名字——**线段树**。

------

一、先拆解问题

所有子数组太多，我们先**固定右端点 i，只看所有以 i 结尾的子数组**：

> `nums[0..i]`、`nums[1..i]`、……、`nums[i..i]`

对每个左端点 `j`，定义：

> `cnt[j]` = `nums[j..i]` 里不同元素的个数。

那么“以 `i` 结尾的所有子数组的不同计数平方和”，就是： `Σ cnt[j]²`。

让右端点 `i` 从 `0` 扫到 `n-1`，每轮累加一次 `Σ cnt[j]²`，就是最终答案。

现在问题变成：右端点从 `i-1` 挪到 `i` 时，新元素 `v = nums[i]` 进场，`cnt[j]` 会怎么变？

`cnt[j]` 统计的是不同元素个数，所以关键就看这个新元素 `v` 是不是新面孔：用 `last` 字典记录每个值上次出现的位置 `p`（没出现过`p = -1`）。

假设 `v` 上次出现在 `p` 位置，那么 `p` 就是一根分界线：

- 左端点 ` <= p` 的子数组从 `p` 的左边或 `p` 本身开始，里面已经包含 `v`。`v` 是老面孔，这些子数组的`cnt[j]` 不变。
- 左端点 ` > p` 的子数组从 `p` 的右边开始，压根没见过 `v`。现在 `v` 在 `i` 位置来了，第一次见，这些子数组的`cnt[j] += 1`。

也就是说，每轮只有左端点在 `[p+1, i]` 这段的 `cnt` 需要更新：给 `cnt[p+1 .. i]` 全体 `+1`。其它 `cnt[j]` 原地不动。更新完后，把本轮的 `Σ cnt[j]²` 累加到答案中。

思路有了，直觉做法就是暴力双层循环：

```python
def sumCounts(nums: List[int]) -> int:
    MOD = 10 ** 9 + 7
    n = len(nums)
    cnt = [0] * n	# cnt[j] = 子数组 [j..i] 的不同计数
    last = {}  		# 值 -> 上次出现的下标
    ans = 0
    for i, v in enumerate(nums):
        p = last.get(v, -1)
        for j in range(p + 1, i + 1):  # 区间加 1：一个一个改
            cnt[j] += 1
        ans = (ans + sum(c * c for c in cnt[:i + 1])) % MOD  # 重扫一遍算平方和
        last[v] = i
    return ans
```

这里两个操作——**区间加 1** 和 **全局求平方和**——暴力都是 `O(n)`。总复杂度 `O(n²)`，`n = 1e5` 直接爆炸。

所以必须找个结构，把"区间加 1 "和"全局平方和"都至少压到 O(log n)。

------

二、从扁平化到层级管理：线段树

扁平化搞不定，那就上树。

把 `cnt` 数组按区间二分。约定根节点编号 `1`，节点 `o` 的左右孩子就是 `o << 1` 和 `o << 1 | 1`，空间开 `4n` 是线段树的常规冗余。根节点管 `[0, n-1]`，往下对半拆。就像任务来了：总监拆给两个经理，经理拆给两个组长，一层层拆到叶子——对，就是最基层的你。

每个节点需要向上一级交两个数：

- `sumv`：我管的这段区间里，所有下标`j`对应的 `cnt[j]` 之和；
- `sqv`：我管的这段区间里，所有 `cnt[j]²` 之和。

老板（根节点）根本不需要认识你，他只要 `sqv[1]`——全局的 `Σ cnt²`，每次更新回溯时都已经自底向上汇总过了，所以能 `O(1)` 拿到。

这就是“全局求平方和”这一半的解法：**不遍历，只汇总。**

那"区间加 1"呢？我们看一个更一般的情况：**整段加 X 的后果，是可以 O(1) 推出来的。**

加 1 就是 `x = 1` 的特例。设某节点手下有 `length` 个人，每个人手里的 `c` 都要变成 `c + x`。新平方和：

```
Σ(c+x)² = Σc² + 2x·Σc + x²·length
```

也就是说，只要这个节点存着旧的 `sumv` 和 `sqv`，下面两行指令就能 O(1) 更新数值：

```python
sqv[o] += 2 * x * sumv[o] + x * x * length
sumv[o] += x * length
```

注意顺序：`sqv` 必须用旧的 `sumv` 来算，算完才能更新 `sumv`——反了就是拿新账算旧账，直接血亏。这也是为什么每个节点除了 `sqv` 还必须存 `sumv`。

但还有个隐患：虽然整段加可以 `O(1)` 算，可如果每次更新都一路拆到叶子，那就退化成 `O(n)` 了。

所以还需要最后一块拼图：**懒标记（lazy）。**

懒标记的意思是：整段被加（要更新的区间整段覆盖了节点所管的区间）时，账先记在自己头上，不往下通知孩子。自己 O(1) 更新 `sumv`、`sqv` ，然后在 `lazy` 上记一笔：“我这段每个人 +x，没通知到本人”。等哪天真的要往下递归，再 `push` 给孩子。

当某次操作**半覆盖**（要更新的区间只是所管区间中的一段）、不得不动孩子时，才把欠账 `push` 下去——两个孩子各自 O(1) 消化，自己的 `lazy` 清零。

“能拖就拖，被查了再说”——拖延不是 bug，是分摊复杂度的手段。

所以，每个节点维护三个东西：

```python
sumv = [0] * (4 * n)    # 节点区间内 cnt 之和
sqv = [0] * (4 * n)     # 节点区间内 cnt² 之和
lazy = [0] * (4 * n)    # 懒标记：整段被加了几次、还没转告孩子
```

`apply`  就是给整段记账的那两行，外加在 `lazy` 上记一笔：

```python
def apply(o: int, length: int, x: int) -> None:
    sqv[o] += 2 * x * sumv[o] + x * x * length
    sumv[o] += x * length
    lazy[o] += x
```

`push` 就是：“孩子们，爹欠你们的账，现在转给你们。”

```python
def push(o: int, length: int) -> None:
    if lazy[o]:
        x = lazy[o]
        left_len = (length + 1) // 2
        apply(o << 1, left_len, x)
        apply(o << 1 | 1, length - left_len, x)
        lazy[o] = 0
```

最后拼上节点 `update` 的完整逻辑：

- 整段被覆盖 → 自己`apply` 记账收工，**不递归**；
- 半覆盖 → 先 `push` 还清旧账（不然孩子数据是脏的），再把任务递给**有交集**的孩子；
- 孩子更新完，父亲从两个孩子重新汇总 `sumv` 和 `sqv`——毕竟还要向上汇报。

```python
def update(o: int, l: int, r: int, ql: int, qr: int) -> None:
    if ql <= l and r <= qr:         # 整段被覆盖：懒，apply 就收工
        apply(o, r - l + 1, 1)
        return
    push(o, r - l + 1)              # 半覆盖：先清旧账，孩子值才准
    mid = (l + r) >> 1
    if ql <= mid:                   # 左孩子有交集
        update(o << 1, l, mid, ql, qr)
    if qr > mid:                    # 右孩子有交集
        update(o << 1 | 1, mid + 1, r, ql, qr)
    sumv[o] = sumv[o << 1] + sumv[o << 1 | 1]   # 孩子更新，父亲重算
    sqv[o] = sqv[o << 1] + sqv[o << 1 | 1]
```

------

三、完整代码

第一节那个内层 for，现在换成一行 update：

```python
from typing import List


def sumCounts(nums: List[int]) -> int:
    MOD = 10 ** 9 + 7
    n = len(nums)

    sumv = [0] * (4 * n)    # 节点区间内 cnt 之和
    sqv = [0] * (4 * n)     # 节点区间内 cnt² 之和
    lazy = [0] * (4 * n)    # 懒标记：整段被加了几次、还没转告孩子

    def apply(o: int, length: int, x: int) -> None:
        sqv[o] += 2 * x * sumv[o] + x * x * length
        sumv[o] += x * length
        lazy[o] += x                    # 账记在自己头上

    def push(o: int, length: int) -> None:
        if lazy[o]:
            x = lazy[o]
            left_len = (length + 1) // 2
            apply(o << 1, left_len, x)
            apply(o << 1 | 1, length - left_len, x)
            lazy[o] = 0                 # 账已转出，清零

    def update(o: int, l: int, r: int, ql: int, qr: int) -> None:
        # 对 [ql, qr] 整体加 1，o 负责 [l, r]
        if ql <= l and r <= qr:         
            apply(o, r - l + 1, 1)
            return
        push(o, r - l + 1)              
        mid = (l + r) >> 1
        if ql <= mid:                   
            update(o << 1, l, mid, ql, qr)
        if qr > mid:                    
            update(o << 1 | 1, mid + 1, r, ql, qr)
        sumv[o] = sumv[o << 1] + sumv[o << 1 | 1]   
        sqv[o] = sqv[o << 1] + sqv[o << 1 | 1]

    last = {}                           # 值 -> 上次出现的下标
    ans = 0
    for i, v in enumerate(nums):
        p = last.get(v, -1)             # v 上次在哪？没有就是 -1
        # j > p 的子数组 [j..i] 里 v 是新面孔，cnt[j] 加 1
        update(1, 0, n - 1, p + 1, i)
        ans = (ans + sqv[1]) % MOD      # 老板看一眼根节点报表
        last[v] = i
    return ans
```

每次 `update` 最多访问 `O(log n)` 个节点，因为递归深度是 `log n`，且整段覆盖时直接 `apply` 拦住，不再往下拆。`n` 轮下来总共 `O(n log n)`，空间三个 `4n` 数组，`O(n)`。`n = 1e5` 时大约百万级的基本操作，能过。

十万人，老板不需要认识每一个人，主循环里那行 `ans = (ans + sqv[1]) % MOD` ，就是老板的全部工作：每来一个新元素，等中层把账做完，扫一眼根节点，下班。
