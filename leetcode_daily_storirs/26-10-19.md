## sort() 先写为敬，然后我学会了数人头

题目大名写着——“找出数组**排序**后的目标下标”。

哟，排序。`sort` 先写为敬：

```python
nums.sort()
return [i for i, num in enumerate(nums) if num == target]
```

O(n log n)，两行搞定，一次 AC。

简单题嘛，主要功能是保温手感。提交完，我照例去题解区溜达一圈，想捡点优越感。

结果优越感没捡着，先挨了一记闷棍：清一色 O(n)，通篇不见 `sort`。人家两个变量就交卷了！

------

#### 不排而定其位

我盯着题目又看了一遍：好家伙，“排序”俩字写得跟主线任务似的，结果是个标题党，专门带节奏。

只是——怎么忍心怪力扣，是我审题审得太认真，被“排序”俩字钓上了钩。

冷静。

回到需求：要的是“排序后 target 的**下标**”。划重点：是下标，不是排序后的完整数组。

问自己一句：排序后，target 会落在哪一段区间？

比它小的，肯定全在前头；跟它相等的，肩并肩连成一整段；比它大的，统统在后面吃灰。

所以压根不需要知道整支队伍长什么样，只要知道 target 那一段从哪儿开始、有多长：

- 起点 = 前面站了多少人 = **比 target 小的个数**，记作 `less`；
- 长度 = 自己人有几个 = **等于 target 的个数**，记作 `equal`；
- 答案 = `[less, less + equal)`。

重心一挪，复杂度跟着挪。一个词的差别，O(n log n) 直接降到 O(n)。

排什么序？数人头就行了。

```python
def targetIndices(nums: List[int], target: int) -> List[int]:
    less = equal = 0
    for num in nums:
        if num < target:
            less += 1
        elif num == target:
            equal += 1
    return list(range(less, less + equal))
```

一趟遍历，两个计数器，不排而定其位。时间 O(n)，额外空间 O(1)。

#### COUNT，不是 ORDER BY

我越想越觉得这操作眼熟——写过 SQL 的人都懂：只求一个名次或区间时，第一反应不是 ORDER BY，是 COUNT。

排序是给想看完整榜单的人准备的；只想要一段区间、一个起点？count 一下就行。

这题要是翻译成 SQL，大概长这样：

```sql
SELECT COUNT(*) FROM nums WHERE num <  target;  -- 这是 less，区间起点
SELECT COUNT(*) FROM nums WHERE num <= target;  -- 这是 less + equal，区间终点
```

`less` 就是 `COUNT(< target)`，`less + equal` 就是 `COUNT(<= target)`，答案 `[less, less + equal)` 正好被这两条 COUNT 前后一夹。我那个 for 循环，无非是把两次扫描合并成了一趟。

COUNT，不是 ORDER BY。真让 MySQL 对着千万行来一发 ORDER BY，EXPLAIN 里那行 `Using filesort` 会红得像体检报告上的箭头，DBA 顺着网线就来找你谈心了。
