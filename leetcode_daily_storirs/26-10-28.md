## 一个 ^，废掉了我整套最短路模板

网格 + 最小 + 路径，力扣经典钓鱼题。你以为是 DP，顺手写下 `dp[i][j] = min(dp[i-1][j], dp[i][j-1]) ^ grid[i][j]`，交上去，红 WA。

为什么？因为异或就像开盲盒——小的异或一下可能变大，大的异或一下可能变小，谁小留谁这套，当场失效。

局部最优走不通，那就老老实实全搜一遍——格子最多 1000 个，先搜了再说。

------

**一、DFS：图可以免建，账不能免记**

图的定义就一句话：一堆点，一堆边。DFS 的活也只有一句话：站到一个点上，把它的邻居挨个跑完，跑到底再折回来。

所以对于 DFS 来说，遍历网格、二叉树、一般图干的是同一个活，区别只在于「邻居名单从哪来」：

- 一般图：名单得提前建，`g[u] = [v1, v2, ...]`——`for v in g[u]`
- 二叉树：名单焊在节点身上，天生最多两孩子—— `dfs(node.left); dfs(node.right)`
- 网格图：没有名单，邻居当场算—— `for di, dj in ((1, 0), (0, 1), (-1, 0), (0, -1))`

这就是网格图最爽的一点：根本不用建图。邻接表被压缩成几个下标偏移量，`grid` 存点权，方向数组存边，二维数组本身就是图的隐式表示。

二叉树走得更极端，边连算都不用算，直接就是结构体上的两个字段。

三者排成一条特例链：二叉树 DFS 是网格 DFS 的简化版，网格 DFS 是一般图 DFS 的免建图版。

不过，图能免建，DFS 的老规矩不能免。动手递归之前，先得回答一个问题：**visited 到底要不要？**

判据只有一条：**会不会绕回原地。**

- 一般图有环 → 不标记就死循环 → visited 保命
- 二叉树天生无环（每个节点只有一个爹）→ 这就是为什么你写二叉树 DFS 从来不加 visited，也从来没炸过。不是你严谨，是结构给你兜底了。
- 四方向网格（岛屿问题）能上下左右乱窜 → 等价于有环 → 必须标记，把格子改成 `0` 就是标记

回到本题 —— **只能向右向下**，连回头的物理可能性都没有。无环。

于是 **DFS** 在这儿完全适用：**状态有限**（格子 `m * n` 个，撑死 1000），**转移明确**（从 `(i, j)` 只能去下、右两个方向），**无环**（`i + j` 一路递增）。

既然无环，那 `visited` 似乎可有可无？——只对了一半。

无环只保证你不会绕圈绕到死，不保证你不做重复劳动。

这题的路径条数是组合数 `C(m+n-2, m-1)`：一个 `31 × 31` 的网格有 961 个格子，却有 `C(60, 30) ≈ 1.18 × 10¹⁷` 条路径——上亿亿条路，不同分支在同一个格子上反复重逢，网格稍微大一点，CPU 风扇就要转行直升机。

所以 `visited` 得有，只不过它这回不是防死循环的安全带，而是防重复计算的**备忘录**。

那新问题来了：备忘录里存什么？

只存`(i, j)` ，等于默认“只要到过这个格子，手里攒的异或值无所谓”——但异或这家伙不像加法，越加越大；它没有单调性，像个叛逆少年，你永远猜不到下一步变成啥。

站在同一个格子上，你手里是 3，他手里是 7，接下来哪怕走一模一样的路：3 ^ 5 = 6，7 ^ 5 = 2，压根不是一个数。只存坐标，就会把“手里拿着 3 的人”和“手里拿着 7 的人”当成同一个人——你以为在剪枝，其实在剪正确答案。

反过来，如果存的是 `(i, j, xor)`：三者都一样，那就说明同一个格子、同样的进格前异或值——后面能走的格子一样，异或序列一样，最终结果必然一样。再搜一遍纯属复制粘贴。

状态从二维升到三维，加一本备忘录 —— 这就是带状态去重的 DFS：

```python
def minCost(grid: list[list[int]]) -> int:
    m, n = len(grid), len(grid[0])
    visited = set()      
    ans = inf

    def dfs(i: int, j: int, xor: int) -> None:
        nonlocal ans
        # 踩到地板 / 出界 / 这个分身跑过了
        if ans == 0 or i >= m or j >= n or (i, j, xor) in visited:
            return                      
        visited.add((i, j, xor))
        xor ^= grid[i][j]
        if i == m - 1 and j == n - 1:
            ans = min(ans, xor)
            return
        dfs(i + 1, j, xor)              
        dfs(i, j + 1, xor)             

    dfs(0, 0, 0)
    return ans
```

注意 `ans == 0` 这行剪枝：异或值非负，0 是理论下界，不可能更小，摸到 0 直接收工。**过程不能剪，下界可以剪**。

------

**二、DP：把递归摊平**

带 `visited` 的 DFS，其实已经是一台 DP 了：`(i, j, xor)` 就是状态，`dfs(i+1, j)` 和 `dfs(i, j+1)` 就是转移，`visited` 就是那本账。

如果我们不一条一条路径去试，而是把每个格子所有可能出现的异或值都存成一个集合，最后在终点的集合里挑个最小的呢？

恭喜，你已经在写 DP 了 —— 思维一转弯，搜索树就变成了递推。

DFS “想到哪搜到哪”，问的是“从起点走到 `(i, j)`，读数能不能恰好是 `xor`？” 

DP 就是反过来收集：**站在 (i, j)，把所有能走到这里的读数一次性列出来**。

> `dp[i][j]` = 从 `(0, 0)` 走到 `(i, j)`，所有可能读数组成的集合。

它和 `visited` 是同一条信息的两面：`visited` 是 DFS 一路摸过去、散点记下“这个格子带着这个读数来过”；`dp` 是按顺序把每个格子的读数集合整理成册。

转移从哪来？能一步走到 `(i, j)` 的只有两位：上爹 `(i-1, j)`、左爹 `(i, j-1)`。两位手里的集合取并，再统一异或上本格：`dp[i][j] = {x ^ grid[i][j] for x in dp[i-1][j] | dp[i][j-1]}`

这里有个必须回答的问题：凭什么敢保证填 `(i, j)` 时，上爹和左爹已经算完了？

答案很朴素：靠的就是图无环。整张图是个 DAG，`i + j` 一路递增就是它的天然拓扑序。逐行逐列扫，正好沿着这个序走：扫到任何一个格子，它上面和左边的那两位必然已经落座：

- 上爹 `(i-1, j)` 在上一行 —— 上一轮循环就扫完了；
- 左爹 `(i, j-1)` 在本行左边 —— 刚才那一格，热乎的。

一个来自上一轮，一个来自刚才，都在手上。不用等，不用回头，一遍过。这就是“无环”两个字最后的价值：DFS 里靠递归栈保证的“先算爹再算子”，DP 里靠遍历顺序白送。

再加个空间优化。`dp[i][j]` 只依赖上一行和本行左边，也就是 `dp[i]` 只依赖 `dp[i-1]`——前面那些行用完就能扔。一行数组原地滚动：

> `dp[j] = {x ^ g for x in dp[j] | dp[j - 1]}`

右边两个 `dp` 各司其职：

- `dp[j]` 还没更新，是上一行同列，也就是**上爹**；
- `dp[j - 1]` 本行刚更新过，也就是**左爹**。

只不过压完有个麻烦：第一行只有左爹，第一列只有上爹，起点俩爹都没有 —— 三个边界，三个 `elif` 分叉。

治边界的老偏方：塞哨兵。多开一格 `dp[0]` 当空气墙：永远是空集，谁也别想从左边界外面走进来；真格子从下标 `1` 开始排，再让 `dp[1]` 开局揣一个 `{0}` 当虚拟起点。

```python
def minCost(grid: list[list[int]]) -> int:
    n = len(grid[0])
    dp = [set() for _ in range(n + 1)]   # dp[0] 空气墙，永远空集
    dp[1] = {0}                          # 虚拟起点：0 ^ grid[0][0] 正好是它本身

    for row in grid:
        for j, g in enumerate(row, 1):
            dp[j] = {x ^ g for x in dp[j] | dp[j - 1]}

    return min(dp[n])
```
