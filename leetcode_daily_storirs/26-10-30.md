## 最短路还要限制连击？**Dijkstra 老司机，请报一下你的连击数**

直接拿普通 Dijkstra 梭哈这题，三个样例能挂俩。

普通最短路只关心一件事：**我现在在哪。**

这题还得关心第二件：**我到这儿的时候，末尾已经连续叠了几个相同字符。**

所以你不能只让 Dijkstra 老司机一个人开车，还得在副驾塞个连击裁判，专门盯着连续相同字符有没有超过 `k` 个。老司机负责算最短路，裁判负责数连击，两人共用一辆车，一个看路，一个看数，谁也别想甩锅。

------

**一、模板：先把骨架变成肌肉记忆**

先过一遍 Dijkstra 老司机的开车套路。模板建议直接背走，背完至少不会把车开进沟里：

```python
import heapq
from math import inf


def dijkstra(graph: list[list[tuple[int, int]]], start: int, n: int) -> list:
    dist = [inf] * n          # 唯一的事实来源：起点到每个点的当前最好成绩
    dist[start] = 0           # 自己到自己，0
    heap = [(0, start)]       # 小根堆，(距离, 节点)——距离必须放第 0 位

    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:       # 懒删除：这是一条过期快照，扔掉
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(heap, (d + w, v))

    return dist
```

Dijkstra 三件套，一个都不能少：

**1. `dist` 数组是唯一的事实来源。** 堆里那些 `(d, u)` 全是"当时的猜测"，`dist` 才是"现在的最优解"。所有判断以 `dist` 为准，堆只负责一件事：决定下一个先处理谁。

**2. 距离必须放元组第 0 位。** Python 的 `heapq` 比较元组是逐位比的，谁在第 0 位谁就是排序键。另外提一句，Python 只有最小堆，想要最大堆就把权值取负塞进去，出来再取回来。

**3. `if d > dist[u]: continue`**。行话叫**懒删除** ——同一个点可能被推进堆好几次：先有 10，后来发现有 6，又推一次。于是堆里同时躺着 `(10, u)` 和 `(6, u)`。弹出 `(6, u)` 时正常处理；等 `(10, u)` 出来，`10 > dist[u] == 6`，说明这是历史遗留数据，直接跳过。

为什么要"出来再扔"这么被动？因为 `heapq` 没有 `decrease-key`——你想把堆里某个元素的值改小，只能先找到它、删掉、再重插，而它藏在哪个位置你根本不知道。懒删除的奥义——改不了就不改，反正过期的我认得出来。

好处是不用维护 `visited` 数组，代码短；代价是堆里多躺几个过期快照，复杂度得写成 `O(m log m)` 而不是 `O(m log n)`。不过 `m ≤ n²`，`log m ≤ 2 log n`，连通图上是同一个量级，无所谓。

最后一个小技巧：只关心到某个终点的距离时，**终点一出堆就可以直接 `return`**，不用把整张图跑完。

**二、今天这题：给最短路装个连击槽**

前面说了，今天光靠老司机一个人不行——普通 Dijkstra 的状态只有一句台词：

> `dist[u]` = 到 `u` 的最小边权和。

从 `u` 继续往下开的时候，老司机只知道“我到 `u` 了，油钱花了多少”，副驾的连击裁判却要问一个他答不上来的问题：

> **“你到 u 的时候，已经连击了几个同款字符了？”**

不知道这个数，下一步就没法判断新字符是接着连击，还是清零重开，更没法判断这一脚会不会直接踩过 `k`。

没什么是多记一笔解决不了的——状态从一维升级成二维，给最短路装个连击槽：

> `dist[u][cnt]` = 到达节点 `u`，且路径末尾有 `cnt` 个连续相同字符时的最小边权和。

`cnt` 的取值范围是 `1` 到 `k`：连击数至少是 1（节点自己就占一个字符），而超过 `k` 的状态压根不合法，不用建。所以数组开 `k + 1` 格，第 0 格永远空着，纯粹为了让下标读起来顺眼。

起点是 `dist[0][1] = 0`。注意是 1 不是 0——起点自己也算一个字符，它也要打卡，不能白嫖连击槽。

```python
# dist[u][cnt]：走到 u、末尾有 cnt 个连续相同字符时的最小总边权
dist = [[inf] * (k + 1) for _ in range(n)]
dist[0][1] = 0
```

到这儿，老司机不再是"到 `u` 就完事"，而是"到 `u` 且末尾连击为 `cnt`" 才算一个完整状态。连击裁判有数可数，老司机就能知道下一脚该不该踩刹车。

状态有了，那从 `(u, cnt)` 出发走一条边到 `v`，新状态怎么算？只有两种情况：

- 新来的 `v` 和当前末尾 `u` 同款字符：连击 `+1`；
- 不同款：连击断掉，但新字符自己算一个，所以重置为 `1`，不是 `0`。

```python
new_cnt = cnt + 1 if labels[u] == labels[v] else 1
```

算完 `new_cnt`，连击裁判立刻过一眼：超没超 `k`？超了就直接 `continue`，这条路当场作废。

```python
if new_cnt > k:  # 连击爆表，这条路作废
    continue
```

整段代码，就是在标准 Dijkstra 上多加了一个维度：

```python
from math import inf
import heapq


def shortestPath(n: int, edges: List[List[int]], labels: str, k: int) -> int:
    graph = [[] for _ in range(n)]
    for u, v, w in edges:
        graph[u].append((v, w))

    # dist[u][cnt]：走到 u、末尾有 cnt 个连续相同字符时的最小总边权
    dist = [[inf] * (k + 1) for _ in range(n)]
    dist[0][1] = 0

    # (总边权，当前节点，末尾连续相同字符的个数)
    heap = [(0, 0, 1)]
    while heap:
        d, u, cnt = heapq.heappop(heap)
        if d > dist[u][cnt]:        # 过期快照，扔
            continue
        if u == n - 1:              # 终点一出堆就是答案
            return d
        for v, w in graph[u]:
            # 同字符接着连，不同字符清零重开
            new_cnt = cnt + 1 if labels[u] == labels[v] else 1
            if new_cnt > k:         # 连击爆表，这条路作废
                continue
            new_dis = d + w
            if new_dis < dist[v][new_cnt]:
                dist[v][new_cnt] = new_dis
                heapq.heappush(heap, (new_dis, v, new_cnt))

    return -1                       # 堆空了还没摸到终点，无路可走
```

**三、底层保证：凭什么这么贪是对的**

上面有好几处"看起来显然"，快速过一遍，每条给个交代。

**非负边权是全部前提。**只要边权非负，绕路就永远不可能比直达便宜——这是 Dijkstra 贪心的根基。堆里当前 `d` 最小的状态，不可能被后面更长的路翻盘。反证法安排上：如果还有更短的，它对应的状态 `d` 更小，按小根堆的规矩早该先弹出来截胡了。老司机不是抢跑，是排序规则说了算。

**懒删除为什么不影响正确性。** `dist[u][cnt]` 只会越更新越小，最后一次更新就是它的最优值，而那次更新塞进堆的记录必然还在堆里，迟早会被弹出来。其余那些过期快照，全被 `d > dist[u][cnt]` 一句拦下。本质上等价于一个 `visited` 数组，只是把“判重”从入堆时挪到了出堆时。

**终点一出堆就能返回。** 出堆顺序单调不减，第一个弹出来的终点，就是所有终点里最小的那个，没有之一。而且本题里任何 `(n - 1, cnt)` 都是一条完整合法路径——人到终点了，字符也拼完了，连击也没超标。

**`new_cnt > k` 的剪枝不会误杀。** “已经出现了 `k + 1` 个连续相同字符”是个既成事实，后面怎么走都改不掉。你没法回到过去把那几个字母删了，也没有时光机版本的 `backspace`。既然一旦违反就永远非法，当场剪掉就是纯赚，不会丢掉任何合法解。

说到底，约束只要能塞进状态、且违反后不可撤销，它就不再是约束了，只是新图里少了几条边。
