## **镜子负责换向，DP 负责记账**

"如果一次反射将机器人移动到一个有镜子的格子，机器人会立即再次被反射"——读起来像逼你写个 `while` 一路弹到底，还得顺手处理弹飞出网格的情况。

真动手你会发现，这个镜子从头到尾只干一件事：**改方向**。

竖着来，横着走；横着来，竖着走。

就这么一条规矩。连续反射不是新机制，只是换向动作被下游格子接着触发。

------

**一、镜子：无停留换向节点**

可以想象成一块 `\` 型 45° 斜面镜，把「横」掰成「竖」，把「竖」掰成「横」。

题面说得很清楚，机器人是**试图移入一个有镜子的格子时，在进入前**被反射的。所以镜子就像无停留的换向节点：

- 朝镜子竖直向下走：被甩向右；
- 朝镜子水平向右走：被甩向下。

这么一看，"连环反射"就没什么神秘的了。不用在单格里写 `while` 弹到底：当前格只处理一次换向，把计数交给下游；如果下游还是镜子，下一格转移继续换。

**DP 一格一格扫，天然把连环反射串成了流水线，不用手摇。**因为机器人只会向右和向下，每走一步 `i + j` 至少加一：整张图是 DAG，逐行逐列就是它的拓扑序，填到任何一格，上游必然已经算完。

反射到界外怎么办？也很简单：这份计数没有下游格子接盘，自然蒸发。不用额外写 `if` 给它办葬礼。

------

**二、状态：方向才是灵魂**

刷过「不同路径」系列的，都背得出来老公式：

> `dp[i][j] = dp[i-1][j] + dp[i][j-1]`

一格一个数，扫完收工。它敢这么省，是因为藏着一个隐含前提：**到了这格之后能干什么，跟你怎么来的无关。** 从上边下来还是从左边过来，结局都是"人站在 `(i, j)`"，未来分毫不差，两条来路合并计数就行。

今天多了面镜子。

同一面镜子，横着撞进来的人和竖着撞进来的人命运完全不同：一个被掰向下，一个被掰向右。两种来法，两种未来——所以状态必须带方向。

把每个格子想成有两条方向通道：一条竖直向下，一条水平向右。定义：

> `dp[i][j][0]`：从 `(i,j)` 以竖直向下方向离开/准备进入下一格的路径数
> `dp[i][j][1]`：从 `(i,j)` 以水平向右方向离开/准备进入下一格的路径数

进入 `(i, j)` 的来源只有两个：

> `from_up = dp[i-1][j][0]`：上一格走竖直通道下来的
> `from_left = dp[i][j-1][1]`：左格走水平通道过来的

有了这两个入口量，转移就是把两种格子（空格/镜子格）的通行方式写下来。

------

**三、转移：空格合流，镜子换向**

**空格（自由节点）**：两条方向通道互通，进来之后往哪走都行。所以上方来的和左方来的全合并：

> `v = from_up + from_left`
> `dp[i][j] = [v, v]`

**镜子（换向节点）**：水平进来的去竖直出口，竖直进来的去水平出口。两个入口量直接换位：

> `dp[i][j][0] = from_left   # 水平来的，被甩去竖直出口`
> `dp[i][j][1] = from_up     # 竖直来的，被甩去水平出口`

**起点**：人已经站在起点上了，走竖直通道和走水平通道各算一种走法，两条通道各揣一个 1 开局。

> `dp[0][0] = [1, 1]  # 首步向右 / 首步向下各注入 1 个方向状态`

------

**四、终点：取 [0] 还是 [1]？**

严格讲，要的是"到达终点的路径数"，也就是终点那格的 `from_up + from_left`：进入终点的两条来路之和 `dp[m-2][n-1][0] + dp[m-1][n-2][1]`。

但题目保证终点 `grid[m-1][n-1] == 0`。终点是空格，空格转移会把两条来路合流成 `v`，并且 `dp[m-1][n-1][0] = dp[m-1][n-1][1] = v`。所以取哪个都行，取 `dp[m-1][n-1][0]` 纯属偏爱。

反过来想更有意思：终点要是镜子，这题直接无解——一次反射就把机器人送出网格，压根停不下来。

------

```python
def uniquePaths(grid: List[List[int]]) -> int:
    MOD = 10 ** 9 + 7
    m, n = len(grid), len(grid[0])
    dp = [[[0, 0] for _ in range(n)] for _ in range(m)]
    dp[0][0] = [1, 1]  
    for i in range(m):
        for j in range(n):
            if i == 0 and j == 0:
                continue
            from_up = dp[i - 1][j][0] if i > 0 else 0     # 垂直进入
            from_left = dp[i][j - 1][1] if j > 0 else 0   # 水平进入
            if grid[i][j] == 1:
                # 镜子：垂直进水平出、水平进垂直出，两通道互换来源
                dp[i][j][0] = from_left % MOD
                dp[i][j][1] = from_up % MOD
            else:
                # 空格：进来后往哪走都行，两通道合流
                v = (from_up + from_left) % MOD
                dp[i][j] = [v, v]
    return dp[m - 1][n - 1][0]
```

时间 `O(mn)`，每格 `O(1)`；空间 `O(mn)`。

空间还能再省。转移只伸手要两样东西：`from_up` 来自上一行同列，`from_left` 来自本行刚算完的左边那格。前者留一整行数组，后者一个往右滚的变量就够，三维表能压到 `O(n)`。

------

**尾声**

题面用词很讲究：机器人是「试图移入」镜子格，然后被反射。

试图——它一步都没踏进那格镜子，去向却被那格镜子改了。dp 表忠实地记下了这件事：镜子格那两个数，存的都不是「站在这格的人」，是「被这格改过方向的人」。

有些格子你从没进去过，但它决定了你往哪走。
