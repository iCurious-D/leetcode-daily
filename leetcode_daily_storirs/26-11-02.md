## 当元素们开始双向奔赴，中位数闪亮登场

昨天 453 那个"`n - 1` 个元素一起 +1"，听起来像全员涨薪，其实等价于“全体先 +1，再挑一个元素 -1”。全体 +1 改变不了任何两个元素间的差距——放现实里就是通货膨胀，大家工资条上的数字都变好看了，购买力一分没涨。

所以 453 的本质操作只有一句：**每次选一个元素 -1**。只能相对往下削，最优目标被最小值按在地板上：所有高于 `min` 的元素都向 `min` 看齐。答案是 `sum(nums) - len(nums) * min(nums)`。

今天 462 的操作是：**每次选一个元素 +1 或 -1**。 

别小看多出来的这个 `+1`，这相当于昨天只有下降通道，今天突然开了双向车道。最终公共值 `t` 不再被 `min` 锁死，而是可以在数轴上自由挑。

那么问题就从一道算术题，升级成一道优化题：`t` 到底选在哪儿，才能让总操作次数最少？

------

**1. 中位数：最小化绝对距离的神**

假设最终所有元素都变成 `t`，每个元素从 `nums[i]` 走到 `t`，需要 `|nums[i] - t|` 步，所以总操作次数是：

> `f(t) = Σ|nums[i] - t|`

这就是经典的 **L1 成本**，人话叫"绝对误差和"。它有一条祖传性质：

> **当 `t` 取中位数时，`f(t)` 最小。**

为什么？把数组排好序：`a[0], a[1], ..., a[n-1]`，先把最小的 `a[0]` 和最大的 `a[n-1]` 配一对。无论最终目标 `t` 在哪，这俩到 `t` 的距离之和都 `≥ a[n-1] - a[0]`（三角不等式）；而当 `t` 落在 `[a0, a[n-1]]` 这个区间内部时，刚好取到这个下界。

继续往里配对：`a[1]` 和 `a[n-2]`、`a[2]` 和 `a[n-3]`……每一对都希望 `t` 落在它们俩中间，这样才能取到距离下界。**中位数妙就妙在：它能同时落在所有这些“首尾区间”里，让每一对都取到下界**。

换个皮肤，这就是个日常约饭问题：一群人约饭，餐馆选在哪儿，所有人走路总距离最短？

答案不是最有钱那位家门口，也不是最好吃的那家网红店，而是住中间那位附近。中位数让左右两边人数平衡。往左挪一步，右边一大片人全体多走；往右挪一步，左边一大片人全体多走。中位数看起来不起眼，但它才是“大家约饭的最短总路程地点”。

```python
def minMoves2(nums):
    nums.sort()
    n = len(nums)
    median = nums[n // 2]  
    return sum(abs(num - median) for num in nums)
```

奇数长度时，中位数唯一；偶数长度时，中间两个数之间的整个区间都最优。取 `nums[n // 2]` ，相当于从中位区间里挑了右端点，没毛病。

复杂度：排序 `O(n log n)`，遍历 `O(n)`；额外空间 `O(1)`，排序空间取决于语言实现（Python Timsort 最坏 `O(n)`）。

**2. 为什么平均数不行：离群点一票否决**

看到这里肯定有人不服：凭啥不能取平均数？“大家向平均值靠拢”听起来更公平，数学味还足。

想法很美好，现实很骨感。拿 `[1, 2, 3, 100]` 试试：

```
平均数 26.5（取整 26）  ：25 + 24 + 23 + 74 = 146
右中位数 3（取 2 也一样）：2 +  1 +  0 + 97 = 100
```

差了 46。原因很朴素：**平均数对离群点零抵抗。** 100 那位老哥一个人就把整个团队的基准线拽到了 26，所有人都得往他那边跑。搁约饭局上，这叫“一个人住郊区，全城陪他通勤”。

统计学里管这种“抗性”叫**崩溃点**：要塞多少坏数据，才能把这个统计量污染到任意离谱。

- 平均数：`0%`。一个马斯克走进你们办公室，"人均资产"当场过亿。
- 中位数：约`50%`。想污染中位数，你得实打实搞定一半的人。

当然，平均数也不是一无是处，它只是**更适合另一种成本函数**。

| 成本函数              | 最优目标          |
| --------------------- | ----------------- |
| `Σ|t - a[i]|`（L1）   | 中位数            |
| `Σ(t - a[i])²`（L2）  | 平均数            |
| `max|t - a[i]|`（L∞） | `(max + min) / 2` |

选哪个统计量，取决于你想最小化什么“总代价”：

- 算绝对距离和，中位数赢。一人一票，谁也别想靠离群绑架全队。
- 算平方距离和，平均数赢。离群点被平方放大，天然向极端值倾斜。
- 只看最远那个人的距离，`(max + min) / 2` 赢。不追求总量最优，只求最惨那位别掀桌。

所以统计量没有绝对强弱，成本函数决定谁赢。不是哪个统计量更强，而是你想最小化哪种后悔。

**3. 尾声**

1948 年，经济学家 Duncan Black 在研究委员会到底该怎么投票，顺手发了一篇《On the Rationale of Group Decision-making》。他证明了一件事：如果所有人的偏好都能排在一条线上，离自己越近越好，那么在多数决规则下，最后胜出的，总是中间那位选民最想要的方案。

九年之后，Anthony Downs 在《民主的经济理论》里把它推成了政治学中著名的**中位数选民定理**，顺便解释了一个反复上演的现象：为什么两个候选人在初选时互骂对方极端，到了大选却一起往中间挤。

极端负责表达，中间负责赢。世界未必偏爱中间，只是很多时候，中间是唯一不需要说服所有人掉头的方向。
