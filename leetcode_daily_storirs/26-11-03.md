**453削峰、462双向、3736填谷：平等三部曲收官**

前天 453：`n-1` 个元素一起 `+1`，等价于单个元素 `-1`，只有下降车道。目标被最小值按在地板上。

昨天 462：单个元素 `+1/-1`，双向车道全开。中位数靠“左右人数平衡”高票当选。

今天 3736：单个元素只能 `+1`，车道被砍掉一半，只剩上升车道。没有 `-1`，没有后悔药，降级是不可能降级的。

三天摆一块看，其实是目标值 `t` 在数轴上一路往右挪：

| 题目 | 操作                                 | 本质               | 目标 t          | 答案                   |
| ---- | ------------------------------------ | ------------------ | --------------- | ---------------------- |
| 453  | n-1 个元素 `+1`，等价于单个元素 `-1` | 只有下降车道，削峰 | 最小值 `min`    | `sum(nums) - n·min`    |
| 462  | 单元素 `±1`                          | 双向车道，双向奔赴 | 中位数 `median` | `Σ abs(a[i] - median)` |
| 3736 | 单元素 `+1`                          | 只有上升车道，填谷 | 最大值 `max`    | `n·max - sum(nums)`    |

------

**1. 单向上升车道：最大值就是全组 KPI**

假设最终所有元素都变成 `t`。因为操作只有 `+1`，元素只增不减，所以目标 `t` ≥ `max(nums)`。

每个 `a[i]` 爬到 `t` 需要 `t - a[i]` 次 `+1` 操作。因为 `t ≥ a[i]`，差值天然非负，绝对值直接省了。全体操作数加起来：

> `f(t) = Σ(t - a[i]) = n·t - sum(nums) `

这是一条斜率为 `n` 的直线：`t` 每往上抬一格，总操作次数就增加 `n` 次，只涨不跌。既然越往大越贵，那最优解自然贴着下界取： `t` 的最小允许值就是 `max(nums)`。

> ```
> t = max(nums)
> ```

最大值不用动，它就是全组不可谈判的 KPI；其他元素，通通向上对齐，一路 `+1`，直到成为 KPI 本身。

```python
def minMoves(nums: list[int]) -> int:
    return max(nums) * len(nums) - sum(nums)
```

时间 `O(n)`，空间 `O(1)`。这一行看着像扫了两趟（`max` 一趟、`sum` 一趟），但都是 C 层循环，比手写 Python for 快得多。何况 `n ≤ 100`，怎么写都对。

**2. 尾声**

三部曲收官：453 削峰，3736 填谷，答案互为镜像；462 开双向车道，中位数当选。

这三题其实都在问同一件事：“平等”的成本由谁承担。 

- 453：高于 min 的部分全砍掉，成本 = `sum(nums) - n·min`（高的削下来） 
- 462：两边各让一步，成本 = `Σ|a[i]-median|`（高矮一起买单） 
- 3736：低于 max 的部分全补齐，成本 = `n·max - sum(nums)`（矮的爬上去）

差距不会凭空消失，它只是被换算成某个人的操作次数。算法决定怎么换算，规则决定谁来买单。
