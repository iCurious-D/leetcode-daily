

## 流量洪峰里，谁在摸鱼？滑动窗口数给你看

`n` 台服务器排排坐，表面上各司其职，背地里谁被打爆、谁在空转，全看请求往谁头上砸。

平时没人较真，直到流量洪峰拍来，大屏一红，老板第一个 @ 了你：

> “统计一下，在 `[queries[i] - x, queries[i]]` 这个时间段里，有多少台服务器一条请求都没收到？”

乱序的 `logs`、乱序的 `queries`，每个查询都扫一遍全量日志？查询多一点，人先下班了，代码还在工位上循环套娃。

服务器摸鱼是服务器的事，你被查询拖垮就是你的绩效事故。既然不能硬扫，不如换个姿势——先排，再滑。

------

**一、先排：把时间线捋顺**

`logs` 是请求流水账，`queries` 是老板的抽查时间点。虽然两者都是乱序塞给你的，但时间戳的先后关系是确定的——毕竟，时间本身是有序的。

把 `logs` 按时间排序，再把 `queries` 的下标按时间排序——注意排的是下标。因为最后答案要按老板提问的原始顺序交上去。这套“先按方便计算的顺序处理、再按原始顺序回填”的套路，正是离线处理查询的常见做法。

排好序后，`logs` 在时间轴上从左到右整齐排成一列；`queries` 则按查询时间 `q` 非递减依次登场，对应的窗口 `[q - x, q]` 也只会向右平移，或者原地不动，绝不回头。

**二、再滑：一台永不回头的考勤机**

既然窗口只向右挪，左右边界自然也只向右走——所以，处理下一个查询时，完全可以接着上一个窗口的位置继续推进，不必推倒重建。

这就轮到滑窗的两大护法 `left` 和 `right` 登场了。每处理一个查询 `q`，两者各管一头：

- **右指针 `right`**：把 `time <= q` 的日志**全部**纳入窗口——新来的请求，打卡。 
-  **左指针 `left`**：把 `time < q - x` 的日志**全部**踢出窗口——过期的打卡记录，从考勤机里擦掉。

两边都挪完后，窗口里留下的日志正好对应当前查询 `q` 的闭区间 `[q - x, q]` 内的所有请求。

但问题来了：窗口里躺着的全是**收到请求**的服务器日志记录，题目要的却是**没收到请求**的那批。

直觉的写法是：把窗口内出现过的服务器 `sid` 塞进一个 `set`，答案就是 `n - len(set)`——能算，但如果每查一次就重建一遍 `set`，窗口等于白滑。滑窗的主要收益就在于增量维护：**每平移一步只处理进出窗口的几条日志**。

所以，换成增量维护，召唤两个帮手：

- `cnt[sid]`：记录编号为 `sid` 的服务器在当前窗口内收到的请求数量；本题服务器编号从 `0` 到 `n-1`，`cnt` 开 `n + 1` 只是习惯性多留一格。
-  `idle`：在编号 `0..n-1` 的 `n` 台服务器里，当前窗口内 `cnt[sid] == 0` 的台数——它们就是摸鱼服务器。  

初始 `idle = n`，全员摸鱼。毕竟刚上班，谁还不是个待机状态。 

之后跟着指针实时更新：

-  右指针纳入一条日志 `(sid, t)`：先看 `cnt[sid]` 是不是 0：如果是，说明它从摸鱼转为干活，`idle -= 1`；然后不管之前是 0 还是正数，都执行 `cnt[sid] += 1`。
-  左指针踢出一条日志 `(sid, t)`：`cnt[sid] -= 1`，如果减之后 `cnt[sid] == 0`，说明它从干活转回摸鱼，`idle += 1`。

注意这里用的是计数 `cnt[sid]`，不是布尔值。同一台服务器在窗口内可能收到多次请求，踢掉一条不代表它就闲了——只有计数归零，才算真正回归摸鱼状态。

所有该进的日志都进完、该踢的日志都踢完后，`idle` 就是当前查询 `q` 的答案。

```python
def countServers(n: int, logs: List[List[int]], x: int, queries: List[int]) -> List[int]:
    logs.sort(key=lambda log: log[1])
    sids = [log[0] for log in logs]
    times = [log[1] for log in logs]
    m = len(logs)
    ans = [0] * len(queries)

    cnt = [0] * (n + 1)	# cnt[sid]：当前窗口内该服务器的请求数
    idle = n			# 全员摸鱼开局
    right = left = 0

    # queries 按下标排序，从早到晚处理，最后按原始下标填回
    for qid in sorted(range(len(queries)), key=lambda i: queries[i]):
        q = queries[qid]

        # 右指针：纳入 time <= q 的请求（新请求打卡）
        while right < m and times[right] <= q:
            sid = sids[right]
            if cnt[sid] == 0:
                idle -= 1          # 从摸鱼转为干活
            cnt[sid] += 1
            right += 1

        # 左指针：擦掉 time < q - x 的过期打卡记录
        while left < m and times[left] < q - x:
            sid = sids[left]
            cnt[sid] -= 1
            if cnt[sid] == 0:
                idle += 1          # 从干活转回摸鱼
            left += 1

        ans[qid] = idle

    return ans
```

令日志数为 `m`，查询数为 `k`。排序 `O(m log m + k log k)`，滑动窗口 `O(m + k)`，整体 `O((m + k) log(m + k))`，空间 `O(n + k)`（不计输入和排序产生的临时空间）。

------

**尾声**

滑动窗口就像一台永不回头的考勤机：右指针负责让新请求打卡，左指针负责把过期打卡记录擦掉，`idle` 负责告诉老板——“过去 `x` 分钟，有 `idle` 台服务器在岁月静好。”

至于它们是真的闲，还是负载不均的受害者，那是下一个问题。
