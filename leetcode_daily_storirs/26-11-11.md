## 10⁹ 种买卡姿势，几何上只有三个角

凌晨一点，你的训练任务卡在队列里，因为集群没卡了。

你打开云厂商控制台准备扩容，然后被它的定价页劝退了整整三十分钟——47 个折叠面板，19 种实例规格，还有三行小字写着“最终价格以账单为准”。翻译一下就是：你别想算明白。

好在今天只需要看三个 SKU：

- 单买 GPU，`cost1` 一张，你缺 `need1` 张；
- 单买 vCPU，`cost2` 一核，你缺 `need2` 核；
- 整机套餐，`costBoth` 一份，一份含 **1 张卡 + 1 核**，两边需求各顶一个单位。

需求写的是“**至少**”，不是“恰好”。套餐买多了、多顶出来的那部分资源，就是云厂商嘴里的“资源弹性”——在你这里叫“已付费的电子盆栽”：摆着不用也行，反正钱已经在套餐里付过了，不会再按单品补一刀。

再看示例里那两套定价，毫无商业道德：

- 示例 1：GPU `3`、vCPU `2`、套餐 `1`。套餐比任何单品都便宜，一份 1 块钱拿下 1 卡 + 1 核。这不叫定价，这叫新人首月 1 折，商家倒贴拉新的老套路了。
- 示例 2：GPU `5`、vCPU `4`、套餐 `15`。单买两份才 `9`，套餐卖 `15`。这不叫套餐，这叫企业版溢价，专门收割懒得比价的人。

所以，套餐既可能是全场最香，也可能是账单刺客。云厂商赌你不会算，你偏要算给他看。

**一、三维视角：斜面推到卡角**

设你订 `x` 张 GPU、`y` 核 vCPU、`z` 份整机套餐：

```
min   cost1*x + cost2*y + costBoth*z

s.t.  x + z >= need1      # GPU 需求，"至少"
      y + z >= need2      # vCPU 需求，"至少"
      x, y, z >= 0        # 不能负数下单
```

标准线性规划：目标线性，约束是线性不等式。

**可行域长什么样？** 在 `(x, y, z)` 三维空间里，两个 `>=` 加三个非负约束切出来的，是一个**没有盖子的楔形**——朝三个轴变大的方向无限延伸。买得越多当然越满足需求，只是你的钱包不一定同意。

**目标函数长什么样？** `cost1*x + cost2*y + costBoth*z = C` 是一族**互相平行的斜面**（等花费面），`C` 就是账单金额，`C` 越小，斜面越贴近原点。

于是画面很直观了：你捏着一张斜面，朝原点方向一路平移，平移到再往前就要脱离可行域为止——它最后一定**卡在楔形的某个尖角上**。

这就是线性规划的基本事实：**线性目标在无界多面体上的最小值，一定在顶点取到。**（三个单价都 `> 0`，账单有下界，最小值确实存在，不会一路滑到无穷远。）

那这个楔形有几个尖角？三维空间的顶点，需要**三个线性无关的约束同时取等**。手里一共 5 个约束：`x=0`、`y=0`、`z=0`，以及 `x+z=need1`、`y+z=need2` 这两个需求约束。挨个组合筛一遍：

| 同时取等的三个约束                        | 顶点`(x, y, z)`                 | 采购含义                               |
| ----------------------------------------- | ------------------------------- | -------------------------------------- |
| `z=0` + 两个需求约束                      | `A = (need1, need2, 0)`         | 纯按需付费，不买套餐                   |
| `x=0` + 两个需求约束，需 `need2 >= need1` | `(0, need2-need1, need1)`       | GPU 全被套餐填满，vCPU 缺口单买        |
| `y=0` + 两个需求约束，需 `need1 >= need2` | `(need1-need2, 0, need2)`       | vCPU 全被套餐填满，GPU 缺口单买        |
| `x=0` + `y=0` + 一个需求约束              | `C = (0, 0, max(need1, need2))` | 全靠套餐，需求少的那边多出来的资源吃灰 |

记 `m = min(need1, need2)`。中间两行的条件互斥——任一输入下只有一行成立，它们是**同一个顶点 B 的两种写法：`B = (need1 - m, need2 - m, m)`。**谁的需求少，谁先被套餐喂饱。

**三个尖角，就是全部候选**： `10^9` 种买卡姿势，几何上只剩三个点要算。

```python
def minimumCost(cost1: int, cost2: int, costBoth: int, need1: int, need2: int) -> int:
    # 顶点 A：不买套餐，全部按需付费
    res1 = need1 * cost1 + need2 * cost2
    # 顶点 C：全订套餐，需求少的那边多出来的资源拿去跑 CI
    res2 = costBoth * max(need1, need2)
    # 顶点 B：套餐只喂饱需求少的，需求多的那边缺口单买
    if need1 <= need2:
        res3 = costBoth * need1 + cost2 * (need2 - need1)
    else:
        res3 = costBoth * need2 + cost1 * (need1 - need2)
    return min(res1, res2, res3)
```

**二、一维视角：一个旋钮，一条凸折线**

三维图像够漂亮：楔形可行域，等花费面往原点推，最后卡在 A、B、C 三个尖角。

但能不能写得更函数化一点？能——把套餐数量 `z` 拎出来当旋钮，三维楔形压成一维折线，三个空间顶点就变成同一个函数上的三个点。

单价全是正数，`x`、`y` 都按份收钱。所以只要套餐数量 `z` 定了，最优解里 `x`、`y` 只会“缺多少补多少”：

```
z = t                    # 套餐份数，全场唯一的自由旋钮
x = max(0, need1 - t)    # GPU 缺口
y = max(0, need2 - t)    # vCPU 缺口
```

三维楔形塌成一个旋钮 `t`，账单变成 `t` 的一元函数：

```
f(t) = costBoth*t + cost1*max(0, need1 - t) + cost2*max(0, need2 - t)
```

记 `M = max(need1, need2)`（`m` 沿用上一节）。`t` 一旦超过 `M`，两边需求都满足了还在续费，那就是纯给云厂商送年终奖。所以有效范围是 `t ∈ [0, M]`。

`f(t)` 长什么样？三段直线拼起来——因为 `max(0, need - t)` 这种玩意儿在 `t = need` 处会折一下。折点恰好两个：`t = m` 和 `t = M`（如果 `m == M`，两个折点重合，不影响候选集合）。

接下来看看 `f(t)` 的斜率。

为写斜率方便，记 `costNeedMore` 为**需求更多那种资源**的单价：`costNeedMore = cost1 if need1 > need2 else cost2`。

| 区间        | 斜率                       | 每多买一份套餐，账单怎么变                           |
| ----------- | -------------------------- | ---------------------------------------------------- |
| `0 ≤ t < m` | `costBoth - cost1 - cost2` | 一份套餐同时顶一张 GPU 和一核 vCPU                   |
| `m < t < M` | `costBoth - costNeedMore`  | 需求少的一边已被套餐填满，再买只替掉需求多的那边一份 |
| `t > M`     | `costBoth`                 | 已不在有效区间：两边都溢出，再多买纯属给云厂商送钱   |

注意三段斜率一路不减： `costBoth - cost1 - cost2 ≤ costBoth - costNeedMore ≤ costBoth`。

斜率单调部件，意味着 `f(t)` 是 **凸函数**——一个碗，只有一个谷底，不存在“翻过这座山还有更低的山谷”。凸函数在闭区间 `[0, M]` 上的最小值，要么在端点，要么在内部折点：端点是 `0` 和 `M`，内部折点只有 `m`。

所以，**候选还是三个：t = 0、t = m、t = M。**

- `t = 0`：套餐一个不订，GPU 和 vCPU 全部按需单买。
- `t = m`：套餐只买到需求少的那边，正好填满；需求多的那边剩下的缺口，用对应单品补。
- `t = M`：套餐直接买到需求多的那边，它刚好满足，需求少的那边多出来的资源，挂 CI 跑贪吃蛇。

把 `f(t)` 原样翻成代码，然后只算三个候选：

```python
def minimumCost(cost1, cost2, costBoth, need1, need2):
    m = min(need1, need2)
    M = max(need1, need2)

    def f(t):
        return costBoth * t + cost1 * max(0, need1 - t) + cost2 * max(0, need2 - t)

    # f(0) 对应 A，f(m) 对应 B，f(M) 对应 C
    return min(f(0), f(m), f(M))
```

这版和三维顶点版本质等价：三维里说的“卡在尖角”，一维里就是“碗底只在端点和折点”。
