## 右扩一行，左缩一场灾后重建

困难题，先别急着跪——`n = 1e5` 这种数字不是装饰品，是力扣的贴心告警：千万别每个子数组都从头算一遍。不然 `O(n²)` 只是入场券，再套一层就直接 TLE 得很有节奏感。

题目问：“最多 k 次操作以内，有多少个子数组可以变成非递减的”。

我们定义子数组 `nums[l..r]` 的最小操作数为 `cost(l, r)`，答案就是统计 `cost(l, r) <= k` 的区间个数。

所以第一件事：把 `cost(l, r)` 求出来。

操作只有 `+1`，没有 `-1`。所以，每个位置 `i` 的最终高度至少是 `max(nums[l..i])`，也就是从 `l` 到 `i` 出现过的最高值。最少操作次数就是取到这个下界：

```
cost(l, r) = Σ(max(nums[l..i]) - nums[i])     i 从 l 到 r
```

每个位置只补到它左边出现过的最高值，多补一分都是浪费。

公式有了，接着看 `cost` 的两个单调性：

- `r` 右移，`cost` 不减：新加一个元素 `x`，账单只会增加 `max - x >= 0`。
- `l` 右移，`cost` 不增：砍掉最左边的元素后，剩下位置的前缀最大值只会变小或不变，逐项都不增。

第二条是关键。对固定的 `r`，如果某个左端点 `l` 合法，那么比它更靠右的左端点只会让窗口更短、`cost` 更小，所以也合法。因此**合法的 `l` 是从某个最左位置 `L(r)` 开始，一直连续到 `r` 的一整段**。

随着 `r` 往右走，`cost` 只会增加，`L(r)` 也只会往右挪，不会回头——两个指针都只进不退，滑动窗口的最爱。

每固定一个 `r`，合法左端点就有 `r - L(r) + 1` 个，答案直接累加：

```
Σ (r - L(r) + 1)
```

------

**1、先写个暴力当对照组**

理论闭环了，代码还是一片空白：`L(r)` 怎么找、`cost` 怎么增量维护，一个字都没写。

不如先写个暴力当对照组，看看双指针到底在省什么：

```python
ans = 0
for l in range(n):
    mx, cost = nums[l], 0
    for r in range(l, n):
        mx = max(mx, nums[r])
        cost += mx - nums[r]
        if cost > k:
            break
        ans += 1
```

固定 `l` 时，`mx` 一路滚，前缀最大值天然正确。暴力的问题只有一个：每换一个 `l`，`mx` 和 `cost` 都从 `nums[l]` 重新开始滚。一旦数组整体非递减（比如 `[1,2,3,4,5]`），`cost` 恒为 0，`break` 一次都不会触发，直接跑满 `n²/2 = 5×10⁹` 个子数组。泡面都泡化了，程序还在跑。

双指针要做的，就是让 `cost` **增量更新**：右端 `r` 进元素，左端 `l` 出元素，都在旧账上就地调整，而不是每换一个端点就重开一局。

听起来很对称，窗口两端各改各的。但真改起来，右端和左端完全不是一个工作量。

------

**2、真正的难点：右扩一行，左缩一场灾后重建**

先看简单的那一端：**右扩**。

窗口右端进一个 `x = nums[r]`，前面那些人的账单 `cost` 一个字都不用改。只要知道当前窗口最大值 `mx`：

- `x > mx`：`x` 刷新纪录，自己就是新的前缀最大值，`cost` 增加 `0`；
- 否则：`x` 要补到 `mx`，`cost` 增加 `mx - x`。

O(1)，一行搞定。

再看真正的难点：**左缩**。

左缩不是每步都发生：右扩之后，如果 `cost <= k`，窗口合法，直接记账；只有 `cost > k` 时，才需要把左端 `l` 往右挪，删掉 `nums[l]`，直到 `cost` 重新回到 `k` 以内。

```python
ans = 0
l = 0
cost = 0
last = 0  # 窗口最大值的位置
for r, x in enumerate(nums):
    
    # 右扩：x 进窗口
    if x > nums[last]:
        last = r  # x 刷新最大值，代价 +0
    else:
        cost += nums[last] - x  # x 并入，补到窗口最大值
        
    # 左缩：cost 超预算时，删掉左端点直到合法
    while cost > k:
        ...【先搭个架子，坑待会儿填】...
        
    # 合法左端点是 [l, r]，共 r-l+1 个
    ans += r - l + 1 
return ans
```

麻烦在于，**删 `nums[l]` 不是简单地从 `cost` 里减掉一个数**。

`nums[l]` 可能曾经是窗口中某一段区间的“前缀最大值”。你把它删了，这段区间不能没人管，需要它右边第一个严格大于它的元素来接管。

而如果每次左缩都从 `l+1` 扫到 `r` 重算，最坏一次 O(n)；一次右扩又可能触发多次左缩，滑动窗口直接退化回 O(n²)，前面全白推。

所以我们需要能够快速知道：删掉 `nums[l]` 后，它右边第一个更大的元素是谁？

------

**3、单调栈：专门负责“右边第一个更大元素”**

既然不能每次左缩时临时往右找，那么就提前预处理。

定义：`nxt[i] = i 右边第一个满足 nums[nxt[i]] > nums[i] 的位置`。如果右边没有更大的，就记 `nxt[i] = n`，表示统治区间一直到数组末尾。

这类'找下一个更大值'的需求，是单调栈的经典战场：

- 从左往右扫，维护一个值单调不增的栈；
- 遇到 `x = nums[i]` 时，把栈顶所有小于 `x` 的位置弹出来；
- 这些被弹出的位置，右边第一个严格大于自己的元素，正是当前的 `i`。

为什么？因为栈里始终保持递减，一旦来了一个更大的 `x`，栈顶那些比它小的元素就同时找到了答案。每个位置最多进栈一次、出栈一次，整个 `nxt` 数组 O(n) 预处理完。

```python
# nxt[i] = i 右边第一个满足 nums[nxt[i]] > nums[i] 的位置
n = len(nums)
nxt = [n] * n
st = []
for i, x in enumerate(nums):
    while st and nums[st[-1]] < x:
        nxt[st.pop()] = i
    st.append(i)
```

------

**4、回到左缩：先确定 `nums[l]` 管哪一段**

有了 `nxt`，左缩的影响范围能一步定位。`nums[l]` 在窗口里的统治区间很清楚：它只管到“右边第一个比它大的元素”或者窗口右边界为止。记：

```
p = min(nxt[l], r + 1)
```

也就是说，`nums[l]` 作为前缀最大值的统治区间是 `[l, p - 1]`。删除 `l` 时，只需要调整 `[l, p)` 这一段，而不是整个 `[l, r]`。

调整分两步。

**第一步，减掉旧账。**

`nums[l]` 在 `[l, p - 1]` 里让每个元素都补到 `nums[l]`，贡献是：

```
nums[l] * (p - l) - (pre[p] - pre[l])
```

前半句是“段长 × 段最大值”，后半句是“这一段原来的元素和”，两者相减就是这段原本的 `cost`。`pre` 是前缀和，区间和 O(1) 查。

**第二步，让新的老大接手。**

删掉 `l` 后，`[l + 1, p)` 里会按 `nxt` 链冒出一批新的前缀最大值。从 `t = l + 1` 出发，一段一段补：

```
e = min(nxt[t], p)
cost += nums[t] * (e - t) - (pre[e] - pre[t])
t = nxt[t]
```

每段 `[t, e - 1]` 里，`nums[t]` 就是新的前缀最大值，所以这段的账可以整段结清。继续跳到 `nxt[t]`，直到 `t >= p`。

补账时沿着 `nxt` 链走，最后停下的那个 `t`，正好是 `[l + 1, p)` 里新的最大值位置，所以 `last` 可以在这里一起更新：右扩时，如果 `x > nums[last]`，直接 `last = r`；左缩时，如果删掉的正好是 `last`，就把 `last` 换成刚才链上最后停下的位置。

为什么这样做不会退化？因为每个位置沿着 `nxt` 链只被跳过有限次，总跳跃次数是线性的。左缩单次看起来可能跳好几段，均摊下来还是 O(1)，整个滑动窗口仍然是 O(n)。

把上面的拼起来：

```python
n = len(nums)

# 单调栈预处理 nxt：右边第一个严格更大的位置
nxt = [n] * n
st = []
for i, x in enumerate(nums):
    while st and nums[st[-1]] < x:
        nxt[st.pop()] = i
    st.append(i)

# 前缀和：O(1) 算出一段的 cost = 段长 * 段最大值 - 段和
pre = [0] * (n + 1)
for i, x in enumerate(nums):
    pre[i + 1] = pre[i] + x

ans = 0
l = 0
cost = 0
last = 0  # 窗口最大值的位置

for r, x in enumerate(nums):
    # 右扩：x 进窗口
    if x > nums[last]:
        last = r              # x 刷新最大值，代价 +0
    else:
        cost += nums[last] - x  # x 补到窗口最大值

    # 左缩：cost 超预算时，删掉左端点直到合法
    while cost > k:
        p = min(nxt[l], r + 1)

        # 减掉 nums[l] 统治 [l, p) 时的旧账
        cost -= nums[l] * (p - l) - (pre[p] - pre[l])

        # 沿 nxt 链补上新前缀最大值的账，顺便更新 last
        t = l + 1
        new_last = l + 1  # 兜底，正常会被下面覆盖
        while t < p:
            e = min(nxt[t], p)
            cost += nums[t] * (e - t) - (pre[e] - pre[t])
            new_last = t
            t = nxt[t]

        if l == last:
            last = new_last

        l += 1

    # 合法左端点是 [l, r]，共 r - l + 1 个
    ans += r - l + 1

return ans
```

右扩 O(1)，左缩均摊 O(1)，整套滑动窗口 O(n)。这题的前半段靠单调性，后半段靠 `nxt` 链，齐活。
